## 一、项目实况审计 | Current State Audit

### 1.1 技术栈识别（代码实证）

| 层级 | 技术 | 实证位置 | 备注 |
| ---- | ---- | -------- | ---- |
| UI 框架 | **React 19** | `package.json` · `src/main.tsx`（StrictMode） | 非 Next.js |
| 路由 | **react-router 8.4** | `src/App.tsx` `createBrowserRouter` | 数据路由模式 |
| 构建 | **Vite 8** | `vite.config.ts`（3030 端口规范 ✓） | Figma Make 导出管线 |
| 样式 | **Tailwind CSS 4** | `@tailwindcss/vite` 插件 | 无 tailwind.config（v4 原生） |
| 语言 | **TypeScript 5.7 strict** | `tsconfig.json`（strict + noEmit） | tsc 实测 0 错误 |
| 格式化 | **oxfmt** | `package.json` `format` 脚本 | 非 Prettier/ESLint |
| E2E | **Playwright 1.55** | `playwright.config.ts` + e2e/ | 32 视觉基线 + axe |
| 包管理 | **pnpm（Corepack）** | 本次新增 `packageManager: pnpm@11.10.0` | 历史上无 lockfile |

> ⚠️ **认知纠偏**：项目实况为 **Vite SPA**，非 Next.js。标规中 RSC/SSR 相关条款按「网关后端承担、本仓库纯前端控制台」的边界解释。shadcn/Radix 依赖未安装（REPO-METADATA 的 topic 仅代表生态方向）。

### 1.3 关键风险（审计发现）

| # | 风险 | 严重度 | 状态 |

| ② | 无 `.gitignore` → node_modules/test-results/密钥存在误提交风险 | 🔴 阻断 | ✅ 已修复（全量 .gitignore，package-lock.json 明确忽略） |
| ③ | README 徽章指向不存在的 `LICENSE` / `CHANGELOG.md`（死链） | 🟡 高 | ✅ 已修复（Apache-2.0 LICENSE + Keep-a-Changelog 格式 CHANGELOG v1.0.0） |
| ④ | Playwright 强制 `executablePath: /usr/bin/chromium`（linux 分支）→ CI 无此路径必崩 | 🔴 阻断 | ✅ 已修复（默认托管浏览器 + `PLAYWRIGHT_CHROMIUM` 覆盖逃生门） |
| ⑤ | 缺失整套协作风暴板：CONTRIBUTING/SECURITY/COC/Issue×3/PR 模板/labels | 🟡 高 | ✅ 已补全（模版闭环母版适配远程地址与八智能体域） |

| ⑦ | `a11y.yml` 上传 `playwright-report/` 但配置输出到 `e2e/reports/html`（空 artifact） | 🟢 低 | ⏱️ 已在路线图 P2 标注 |

## 三、建议指导与路线图 | Roadmap

### P0（初始化后立即）

1. **推送本提交并观察 CI 首跑**：`Actions` 页逐 Job 核对（重点：install 冻结校验、playwright 浏览器安装）
2. **仓库 Settings 配置**：按 [.github/REPO-METADATA.md](../../.github/REPO-METADATA.md) 设置 Description/Website/Topics；分支保护 main（必需检查：typecheck/lint/build/e2e）
3. **标签一键同步**（可选）：`npx github-label-sync --labels .github/labels.json --allow-added-labels YYC-Cube/YYC3-AI-Family-API-Console`

### P1（本迭代）

4. **GitHub Pages 开通**：Settings → Pages → Source 选 `GitHub Actions`（docs.yml 的 deploy job 方可生效）
5. **release 环境就绪**：Settings → Environments 创建 `production`（release.yml 引用），并在 tag v1.0.0 上实测全链路
6. **契约双仓联动**：与网关后端约定漂移通知路径（每日 02:00 UTC 巡检红的处置 SLA）

### P2（下迭代）

7. **单测基线**：引入 Vitest + Testing Library（标规要求覆盖率 >80%；当前 0 是最大质量缺口），优先覆盖 `useWanyuChat` 七态状态机与 `api.ts`
8. **a11y artifact 路径修正**（风险⑦）+ mmdc 正式安装（风险⑧）+ Lighthouse 断言阈值（风险⑨）
9. ** Dependabot**：启用 pnpm 生态周更 + Actions 版本周更
10. **视觉基线多平台**：评估在 CI 增加 `-linux` 前缀快照集，或统一 `deviceScaleFactor` 消除 darwin/linux 双基线维护成本

### P3（演进）

11. **Next.js 评估**：若 SEO/SSR 需求上升，评估 RSC 渐进迁移（当前纯控制台暂无必要）
12. **八智能体运行时**：从「展示控制台」演进「可编排控制台」（FamilyBus 双向指令）
13. **OTel 前端埋点**：对齐标规 W3C Trace 约定，路由切换/推理链路上报
